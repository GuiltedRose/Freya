# November 7 network-grant attribution and reduction design

## Confirmed accounting and limits

Five operator-reported sessions exhausted their grants. The latest controller
row is RX 384,933 + TX 619,868 = **1,004,801 interface-accounted bytes**, about
38.3% RX / 61.7% TX. The five-session average of roughly 33%/67% is separate.
`grant_exhausted` explains the early controller shutdown; EINTR handling is a
separate corrected issue. No matching capture or latest per-session repair count
is available in this workspace, so a numerical protocol breakdown is not verified.

| Component | Supported attribution |
| --- | --- |
| Repair requests | 160 application bytes per kernel-confirmed request; exact latest-session sum unavailable |
| Repair pongs | Pinned serialized pong is 132 application bytes; at most one per attempt |
| Repair input | No validated shred; this does not imply zero datagrams/pings/rejected traffic |
| RPC planning | Possible TCP/TLS plus DNS and retransmissions; cached-window reuse can avoid planning, but the supplied grant row does not prove that path |
| Gossip | Confirmed active concurrent producer; strong candidate for substantial non-repair traffic, not a measured percentage |
| Other | ARP, ICMP, DNS and unrelated namespace traffic must remain separate where present |

For a still-unresolved single window, all 128 attempts together would send at most
20,480 request payload bytes plus 16,896 pong payload bytes. Under ordinary IPv4
UDP without options/fragmentation, those 256 packets would be 44,544 IP bytes.
This is a conditional upper bound, **not** measured interface TX. It supports
looking beyond the small repair protocol messages to explain 619,868 interface
bytes, but does not identify the residual as gossip. Do not subtract payload
counts from interface totals and label the difference gossip.

Interface bytes, IP `ip.len`, UDP `udp.length` (including eight-byte header), UDP
payload and capture frame lengths are different measurements. Controller sampling
and incoming packets counted before quota rejection can produce an observed total
above the grant; the 4,801-byte excess is not evidence of authorization renewal.
Do not infer provider-accounting or firewall bypass from that total alone.

## Pinned Agave worker audit

`gossip_service.rs::make_node(..., gossip_addr=None, ...)` creates a spy node and
starts `GossipService`; it does not start full validator consensus/TVU services.
The service owns these workers:

- Receiver and socket-consume workers receive/parse/sanitize/authenticate gossip;
  these are needed to populate usable peer advertisements.
- Listener handles requests/responses and can generate pull responses, pushed CRDS
  propagation, prune messages and ping/pong traffic. Keeping only the listener
  would not make the node passive or eliminate outbound traffic.
- `cluster_info.rs::gossip` actively runs `run_gossip`: push generation each round,
  pull generation every fifth round. Target round sleep is 100 ms, so nominal pull
  scheduling is about 500 ms, subject to work/delays. It also refreshes contact
  info/push active sets and purges records. Pull generation includes probe pings.
- Responder sends the queued UDP batches generated by listener and gossip workers.
- Metrics worker reports every two seconds. It is not itself evidence of network
  export; the package wrapper unsets `SOLANA_METRICS_CONFIG`. Capture any actual
  additional flow before attributing bytes to it.

Signature and address filtering remain necessary. `cluster.all_peers()` returns
contacts plus local observation times; Freya then checks version, self exclusion,
30-second freshness and approved repair endpoints. The existing Nix edits reduce
channel/table capacities to 128/512. Those are capacity bounds, not a byte quota
or a guarantee of lower push/pull bandwidth. They do not stop ongoing exchanges.

## Minimal implemented change: measured boundaries, not guessed gossip bytes

Only `native/freya_node/src/follow.rs` changed. New per-session `session_traffic`
records explicit units and counters for kernel-accepted request/pong payload TX,
all repair-socket received/copied bytes and datagram count, plus buffer-full count.
Copied bytes are a lower bound if oversized datagrams were truncated to the receive
buffer; rejected and unexpected packets are included, queued unread packets are not.
These are not signature-valid byte totals or physical-transmission proof.

Up to four interface-counter snapshots measure deltas from the existing session
baseline: planning finished, gossip start, first eligible candidates, and finish.
A missing interface during teardown is marked `final_snapshot_unavailable` instead
of replacing the actual outcome. No RPC is added, prior counters/claims are not
reset, and snapshot/counter fields are scoped to the new repair session ID.
The planning interval includes setup/other concurrent namespace traffic, not only
RPC. Gossip and repair overlap after discovery; phase deltas are not protocol totals.
No unmeasured `gossip_bytes` or `repair_bytes` field is promoted as authoritative.

Twelve exact-helper Rust tests passed in an isolated offline harness, including
baseline subtraction, counter-reset rejection, bounded snapshot history and prior
repair/interrupt/handshake regressions. `git diff --check` passed. Full builds were
attempted but the Nix daemon returned `Connection refused`; complete engine
compilation remains unverified. No live session or new capture was run.

Operator build verification:

```bash

```

Use the existing [refresh/review/backup/activation and rollback workflow](native_network_investigation.md)
when deploying reviewed changes. Both node and peer references must be checked.

## Proposed reduction: bounded discovery snapshot, not a protocol fork

This is a design for implementation/validation after attribution, **not enabled
or claimed tested by this patch**:

1. Discover a finite target such as four independently signed, same-version eligible
   contacts. Keep each identity, exact repair endpoint and original observation
   time. This does not prove independent operators or historical slot retention.
2. Separate gossip's shutdown flag from the follower/systemd cancellation flag.
   Current `make_node` shares that flag with follow: setting it to stop gossip now
   would also stop acquisition. Retain the signing identity, stop and join every
   gossip worker, and keep only the finite candidate metadata. Check join behavior
   against the existing stop timeout; incomplete shutdown must not imply success.
3. Repair only from candidates still passing the existing 30-second freshness
   test, endpoint and signature rules. Do not refresh timestamps merely by selecting
   a cached peer. The existing lease and 40-second overall timer remain authoritative.
4. Alternative endpoints are limited to that authenticated snapshot. There is no
   claim of reconnection/discovery while gossip is stopped. If it expires or is
   exhausted, halt with the gap preserved; no automatic rediscovery/session renewal.

Expected saving is the **measured ongoing gossip flow after transition**, minus
shutdown/in-flight traffic; it is currently unknown. Remote gossip packets may
continue arriving after shutdown and still consume RX quota. The costs are loss
of fresh replacements, remaining usable freshness time, and possible failure if
snapshot peers lack the old slot or refuse service. A default change is unjustified
until these tradeoffs and actual gossip share are established.

Required deterministic/integration gates before enabling: separate cancellation
flags, no gossip sends after joined shutdown, current identity retained, exact
endpoint pinning, expiry at 30 seconds, fallback only within the snapshot, empty
snapshot halt, stale/invalid contact exclusion, quota/lease enforcement during join,
and no resurrection of unresolved slots or automatic restart. Do not simply slow
pull rounds/remove push processing in the pinned source without separate protocol
compatibility tests. No such Agave protocol change is made here.

## Existing-capture attribution and one optional authorized diagnostic

First obtain the matching existing grant/controller events and checkpoint projection:

```bash
sudo jq '{repair_session_id,session_traffic,last_repair,repair_request_history}' \
  /var/lib/freya-node/follow/checkpoint.json
```

Old checkpoints do not retroactively contain the new counters. Export the existing
capture on **one selected interface** during the grant's epoch interval. Replace
the placeholders and use the actual namespace/uplink address, including NAT mapping:

```bash
cap=/absolute/path/to/existing-private-capture.pcapng
tshark -r "$cap" --disable-protocol wg \
  -Y 'frame.interface_id == INTERFACE_ID && frame.time_epoch >= START_EPOCH && frame.time_epoch <= END_EPOCH && ip' \
  -T fields -e frame.time_epoch -e ip.src -e ip.dst -e ip.proto -e ip.len \
  -e udp.srcport -e udp.dstport -e udp.length -e tcp.srcport -e tcp.dstport
```

Group `ip.len` separately by direction and exact known gossip socket, repair socket,
reviewed RPC flow, DNS, ICMP and unknown flows. Include TCP retransmissions; avoid
counting the same packet on both veth and uplink as two packets. UDP socket-based
categories are flow attribution, not proof of payload protocol/authentication.
Exclude unrelated host flows. Fragmented packets without transport headers and
ARP/interface overhead remain explicit accounting differences. Capture drops or
missing setup periods prevent a complete comparison with controller totals.

Only if existing captures are insufficient, explicitly authorize one manual capped
session using the existing 60-second, finite-packet, private two-interface capture
procedure. Record grant ID/expiry, before/after counters, actual gossip/repair socket
owners and phase snapshots. No automatic service start, retry, lease renewal or
new network permission is part of this plan. The 1 MB grant remains unchanged.
The measurement objective is protocol/phase attribution; the acquisition acceptance
criterion remains a real authenticated shred durably retained after shutdown.
